## 短い発話の脱落（2026-10-03 修正）

利用者の実発話「あいうえお」（1.4 秒）が "I will" になった。合成音声でも「こんにちは」「テスト」「はい」「ありがとう」が空で返ることを再現。
原因は WhisperKit が各解析区間の末尾 1 秒を切り捨てる既定動作（`windowClipTime: 1.0`）で、1 秒未満の発話は無視され、
1.4 秒の発話は冒頭 0.4 秒しか解析されていなかった。認識前に末尾へ 1.2 秒の無音を足して解消。

## 挿入判定の修正、Codex CLI 接続、表示名（2026-10-03）

### 挿入されない・コピーボックスが出ない

履歴 29 件のうち 27 件が「挿入のみ」と判定されていた（Claude 21、ChatGPT 3、Chrome 2、LINE 1）。
原因は、選択範囲の情報を返す要素をすべて入力欄とみなしていたこと。Web ページの本文などは、文字を打てなくても選択範囲を返す。
そのため入力欄がない場面でも貼り付けだけ行い、コピーボックスを出していなかった。
また、クリップボードを 0.3 秒で元に戻していたため、反応の遅いアプリでは貼り付け前に内容が戻っていた可能性がある。

対応:

- 入力欄の内容の長さが読める場合は、貼り付け後に長さが変わったかを最大 1 秒確認し、変わらなければコピーボックスを出す。
- 選択範囲の情報だけでは入力欄とみなさない。編集可能かどうか（値や選択範囲を書き換えられるか）を見る。
- クリップボードを戻すまでの時間を 0.8 秒以上に延長。
- 判定の経過を `~/Library/Logs/KoeType/insertion.log` に 1 行ずつ記録（アプリ名・要素の種類・判定・確認結果。入力した文章は記録しない）。

判定ロジックは自動テストで確認。実際のアプリでの挙動は未確認（利用者の操作が必要）。

- 文末の小さな書き換え（「原因だと思います」→「原因だと思われる」）は検査を通り抜ける。未解決。忠実さを重視する場合は OpenAI API を選ぶ。
- メール文体の指示に従わないことがある（同じ入力で丁寧語になる回とならない回があった）。未解決。

### アプリ別の文体

## マイク起動中のフリーズ（2026-10-17）

### 現象と原因

アプリ全体（メニュー、ホットキー、表示）が反応しなくなり CPU 約 40% のまま固まる。プロセスのサンプルでは、
メインスレッドが `AudioRecorder.start()` -> `AVAudioEngine.inputNode` -> Core Audio HAL（`AudioObjectGetPropertyData` /
coreaudiod への mach_msg）から戻らないままだった。既定の入力が Bluetooth ヘッドセット（Shokz OpenComm2）で、
Continuity の iPhone マイク 2 台と仮想機器も接続された環境では、HAL の問い合わせが数秒〜事実上無期限に止まることがある
（特に Bluetooth の通話プロファイルへの切り替え中）。エンジンの生成・`inputNode`・`outputFormat`・入力機器の指定・
prepare/start/stop・removeTap・`AudioDevices` の問い合わせが、すべてメインスレッドで同期に動いていたのが原因。

### 対応

- `AudioRecorder` の AVAudioEngine / Core Audio を触る処理をすべて専用の直列キュー（内部クラス `Worker` が所有）へ移した。
  `start()` / `stop()` / `cancel` はメインから呼ぶが、キューへ積むだけで戻る。`stop()` はこれまでどおり録音済みサンプルを
  同期で返す（取り込みの停止はロック下のフラグで行うため、エンジン停止を待つ必要がない）。
- 開始は 3 秒（`EngineStartPolicy.timeout`）で見切る。開始が完了も失敗も報告しないまま 3 秒経つと、録音を中止し、
  その Worker を放棄して新しい Worker に差し替える（放棄したエンジンは二度と使わず、遅れて起動しても音声を渡さず停止する）。
  利用者には「マイクが応答しないため、入力を中止しました」、起動失敗には「マイクを開始できませんでした」を表示する。
- エンジンの 10 秒保持、Bluetooth 同一マイクの再起動（0.15 -> 0.3 -> 0.6 秒）、世代判定、短押し後のマイク開放維持、
  キー押下前の音声の除外、時間制限、コールバックのメイン配送は従来どおり。
- 見切りと遅延完了の判定は `EngineStartPolicy`（KoeTypeCore）に切り出し、自動テストを追加。

### レビュー指摘の修正（同日）

- 起動が完了する前に次の録音が始まると（2 回押しの 2 回目など）、起動したばかりのエンジンを捨てて
  もう一度マイクを開いていた（Bluetooth のプロファイル切り替えが増え、HAL が止まる条件を自ら作る）。
  遅延完了したエンジンは「放棄した Worker のもの」である場合だけ捨て、それ以外は世代に関係なく保持して
  開放維持と次の録音の再利用に回すよう修正（取り込む音声はもともとレコーダー側のロック下の状態で絞っている）。
- 起動失敗の通知（`microphoneUnavailable`）は、メインキューで再度世代を照合してから配送する。
  放棄済みの Worker の起動失敗は通知しない（「応答しない」の後に「開始できません」が重ねて出ない）。
- HAL が永久に止まった場合、放棄した Worker（とそのスレッド）は戻るまで残る。見切りは 3 秒に 1 回しか起きず、
  GCD のスレッド上限内に収まる想定で、上限は設けていない。

### 2 回目のレビュー指摘の修正（同日）

- 構成変更の処理（Bluetooth のプロファイル切り替え）で HAL への問い合わせが止まり、その間に見切りで新しい録音が
  始まった後に遅れて「マイクが切り替わった」と判定されると、新しい録音を止めてしまっていた。
  問い合わせの前に対象の世代を固定し、戻った後に Worker の放棄と世代を再確認してから、その世代宛てに通知する。
  メイン側でも Worker が現役で、放棄されておらず、世代が一致するときだけ配送する。
- 見切りの対象を起動だけから「止まりうる処理の区間」全体へ広げた。起動、構成変更の処理、再起動の各試行を番号付きの
  作業として記録し、3 秒以内に完了報告がなければ同じ経路（Worker 放棄 -> 差し替え -> `microphoneUnresponsive`）で見切る。
  再起動の 0.15 -> 0.3 -> 0.6 秒の待ちはそのまま。加えて、起動完了を報告したのに 3 秒間 1 つも音声バッファが届かない
  録音も同じ扱いにする（短押しで終わった録音や、より新しい録音がある場合は対象外）。
  録音の途中で見切った場合は、それまでに取り込んだ音声を入力に回し「マイクが応答しないため、ここまでを入力します」と出す。
  何も取り込めていなければ従来どおり「入力を中止しました」。
- 「マイクを聞き比べる」ボタンと設定画面のマイク一覧は、機器の列挙（HAL 問い合わせ）をメインキューの外で行う。
  設定画面は 1 秒ごとの再列挙が重ならないよう、列挙中は次を飛ばす。
- 放棄した Worker に残っていた起動・開放維持・停止の処理は、HAL が戻っても何もせずエンジンを閉じるだけにした
  （遅れてマイクを開き、新しい録音の最中にヘッドセットのプロファイルを切り替えない）。
- 見切りと起動失敗の報告が同時に起きても、作業番号で先に見切った側が勝ち、「開始できませんでした」が重ねて出ない。

### 3 回目のレビュー指摘の修正（同日）

- 放棄した Worker が、止まっていた呼び出しから戻った後も先へ進んでいた（起動では HAL 問い合わせの後にエンジン生成と
  `run`、失敗時はさらに作り直して 2 回目の `run`）。起動・再起動・構成変更の処理で、止まりうる呼び出し（機器の問い合わせ、
  `inputNode`、`outputFormat`、`prepare`/`start`）の後ごとに放棄を確かめ、放棄されていればエンジンを閉じて終わるだけにした。
  `run` の途中で放棄に気づいた場合は `abandoned` エラーで抜ける。
- 作業の完了を「報告済みの最大番号」で追っていたため、番号が順不同で始まり終わると（構成変更の通知スレッドが先に番号を
  取る、構成変更の中の再起動が後の番号を先に終える）、それより小さい番号の起動が止まっても見切られなかった。
  完了は作業番号ごとの集合（未完了の番号）で追い、見切りは「その番号がまだ未完了で、録音が現在のもの」のときだけ。
  見切りと起動失敗の報告は同じロック内で番号を取り合い、先に取った側が勝つ。順不同完了のテストを追加。
- 機器の列挙は `Task.detached`（協調スレッドプール）ではなく、`AudioDevices` が持つ専用の直列キューで行い、
  continuation で待つ。列挙中に来た要求は新たに積まず、進行中の結果を共有する。
- 設定画面のマイク一覧は、最初の列挙が戻るまでは保存されている個別機器の選択を「選択中のマイク」として
  一覧に載せ、Picker の選択値に対応する項目が無い状態を作らない。

### 4 回目のレビュー指摘の修正（同日）

- `prepare()` の後 `start()` の前と、エンジン生成時の機器の問い合わせ・`inputNode` の後 `AudioUnitSetProperty` の前にも
  放棄の確認を入れ、Worker 内で止まりうる呼び出しの後は必ず次の「開く・設定する」手前で確かめるようにした
  （放棄後は機器を設定せず、呼び出し元がエンジンを閉じる）。
- 見切りの判定は、その作業の Worker が現役で放棄されていないことを先に確かめ、そうでなければ状態に触れず作業を
  捨てるだけにした（放棄済み Worker の作業が同じ世代番号を持っていても、新しい録音を黙って止めない）。
- 構成変更の通知は、処理が待ち行列にあるか実行中の間は新たに積まず「もう一度見る」印だけ付け、処理の終わりに
  印があれば改めて 1 回だけ処理する。待ち時間と処理時間は別々の作業として見張る（待ちの作業で詰まった待ち行列を検出し、
  処理の作業は実際に走り始めてから 3 秒）。Bluetooth の切り替えで通知が連続し、再起動が 0.2〜1 秒ずつ並んでも
  「応答しない」と誤判定しない。
- 「マイクを聞き比べる」は、機器の一覧が 3 秒で返らなければボタンを戻し「マイクの一覧を取得できませんでした。
  もう一度お試しください」と出す。

### 6 回目のレビュー指摘の修正（同日）

- 無音の見張りは、ロックの中で「その Worker が現役で放棄されておらず、世代が現在のもの」と確かめたときだけ張る
  （`EngineStartPolicy.armsSilenceWatch`）。差し替え済みの Worker が遅れて起動報告しても、新しい録音の見張りを上書きしない。

### 残件 4 点の修正（同日、7 回目の合格後）

### 機器を指定したときの起動失敗（-10868、同日）

- 現象: 設定でマイクを個別機器（例: Shokz `<Bluetooth機器のUID>:input`）にすると、毎回「マイクを開始できませんでした」。
  #6 以前の 697fc4f でも同じ（`engineFailed(... Code=-10868 ... InitializeActiveNodesInInputChain)`）で、#6 の退行ではない。
  システム既定のまま同じ Shokz を使うと成功する。
- 原因: エンジンの入力ノードを `kAudioOutputUnitProperty_CurrentDevice` で別の機器に向けても、ノードの出力形式は
  作った時点の機器の 48 kHz のまま残る。Shokz は通話プロファイルで 16 kHz のため、`format: nil` のタップがその古い
  48 kHz に従い、入力ノードは標本化周波数を変換しないので初期化で -10868 になる。検証用の小さなプログラムで、
  機器指定後の `inputFormat` が 16 kHz・`outputFormat` が 48 kHz のままで起動に失敗すること、出力側の形式
  （`kAudioUnitProperty_StreamFormat`、出力スコープ・バス 1）をハードウェアの周波数とチャンネル数に合わせると
  `outputFormat` も 16 kHz になり起動して音声が届くことを確認。48 kHz の内蔵マイクと iPhone マイク 2 台は、指定しても
  もともと成功していた。
- 対応: 個別の機器を指定したエンジンに限り、`run()` でタップを付ける前に、ハードウェアの形式と入力ノードの出力形式が
  周波数かチャンネル数で食い違っていれば、出力形式をハードウェアに合わせる（`InputFormatAlignment.needed`、テスト 2 件）。
  タップは従来どおり `format: nil`、16 kHz への変換はタップ内で行う。システム既定に従うエンジンでは、形式の照会も
  設定も一切行わない（0f7d5a7 以前と同じ）。設定に失敗した場合（3 チャンネル以上で標準形式が作れない等）は何もせず、
  修正前と同じ失敗経路になる。
- 再レビュー（7420bf1）: Opus は合格、Codex は不合格（形式合わせが既定追従にも及ぶ、待ち手の期限だけを 3600 秒で
  切っていた）。既定追従では何もしないようにし、秒数は最初に 1 回だけ範囲内に収めて呼び出し側の待ちと待ち手の両方に使う。
  まとめた再処理は「処理中」のまま引き渡し、その間に届いた通知が再処理の世代を上書きしないようにした。
