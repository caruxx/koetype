## 短い発話の脱落（2026-10-03 修正）

利用者の実発話「あいうえお」（1.4 秒）が "I will" になった。合成音声でも「こんにちは」「テスト」「はい」「ありがとう」が空で返ることを再現。
原因は WhisperKit が各解析区間の末尾 1 秒を切り捨てる既定動作（`windowClipTime: 1.0`）で、1 秒未満の発話は無視され、
1.4 秒の発話は冒頭 0.4 秒しか解析されていなかった。認識前に末尾へ 1.2 秒の無音を足して解消。

| 発話 | 修正前 | 修正後 |
|---|---|---|
| こんにちは | （空） | こんにちは |
| テスト | （空） | テスト |
| はい | （空） | はい。 |
| ありがとう | （空） | ありがとう。 |
| 了解です | 了解です。 | 了解です。 |
| あいうえお | （空） | あいゆえよ（意味のない音の並びは合成音声でも不正確） |

長文 10 本と無音 3 秒は修正後も結果が変わらないことを確認。

## 最終レビュー後の修正（2026-10-03）

独立したレビュアー（Opus）の指摘 7 件に対応した。

| 指摘 | 対応 | 確認方法 |
|---|---|---|
| 自分が送る Cmd+V を「他のキー」と誤認し、次の録音を取り消す | 自前のキーイベントに印を付けて無視 | 自動テスト |
| 左 Command を押したまま右 Command を離すと解放を見逃し、マイクが開いたままになる | 左右を区別する装置別ビットで判定 | 自動テスト |
| 右 Command + クリック / スクロールで録音が走り、周囲の音を入力してしまう | マウス操作も「他の入力」として録音を取り消す | 自動テスト（分類）。実機は未確認 |
| 監視が一時停止した後に解放を見逃す | 再開時に現在のキー状態と突き合わせる | 自動テスト（分類）。実機は未確認 |
| オフラインで起動するとモデルを読み込めない | モデルが手元にあれば通信せずに読み込む | CLI で読み込み 2.2 秒を確認。通信を切った状態での起動は未確認 |
| 通常のショートカットのたびに録音表示がちらつく | 表示と拒否メッセージを 0.2 秒遅らせ、他のキーが来たら出さない | 実機は未確認 |
| 30 秒を超える発話で文が脱落する | 時刻情報で解析位置を進める方式に変更 | 70 秒の音声で確認（下表） |

### 30 秒を超える発話

10 文に番号を付けた 70 秒の合成音声。

| 設定 | 結果 | 時間 |
|---|---|---|
| 修正前 | 4 番目の文が丸ごと脱落、「九番目」が「10番目」に | 3.7 秒 |
| 修正後 | 10 文すべて正しい | 4.7 秒 |

修正後は、末尾に足した無音から「ご視聴ありがとうございました」「ありがとうございました」が生成される例が出たため、
音声の終わり際（0.5 秒以内）に始まる定型の結び文句を捨てる処理を追加した。実測した区切りの時刻をテストに入れてある。
短い発話 6 件、長文 10 件、無音 1 件は修正後もすべて期待どおり。
