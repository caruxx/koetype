## 短い発話の脱落（2026-10-03 修正）

利用者の実発話「あいうえお」（1.4 秒）が "I will" になった。合成音声でも「こんにちは」「テスト」「はい」「ありがとう」が空で返ることを再現。
原因は WhisperKit が各解析区間の末尾 1 秒を切り捨てる既定動作（`windowClipTime: 1.0`）で、1 秒未満の発話は無視され、
1.4 秒の発話は冒頭 0.4 秒しか解析されていなかった。認識前に末尾へ 1.2 秒の無音を足して解消。

| 発話 | 修正前 | 修正後 |
|---|---|---|
| こんにちは | （空） | こんにちは |
| テスト | （空） | テスト |
| はい | （空） | はい。 |
| ありがとう | （空） | ありがとう。 |
| 了解です | 了解です。 | 了解です。 |
| あいうえお | （空） | あいゆえよ（意味のない音の並びは合成音声でも不正確） |

長文 10 本と無音 3 秒は修正後も結果が変わらないことを確認。

## ローカル処理優先と Luna 接続（2026-10-03）

- 既定を「ローカルのみ」に変更。AI 整形は設定で選んだときだけ使う。
- ローカル処理で「えーと」「えっと」「あのー」「うーん」、文頭や読点の後の「えー」「あの、」を除去（自動テスト）。
  合成音声「えーと、あのー、明日の会議なんですけど、えっと、十時からに変更になりました。」で、
  Whisper の出力「えーと、あの、明日の会議なんですけど、えっと、10時から2変更になりました。」から
  フィラーが除かれることを確認。「に」が「2」になったのは合成音声の認識誤りで、ローカル処理では直らない（AI 整形の対象）。
- AI に送るのは既定で 20 文字以上の発話のみ（設定で 0〜200 文字）。短い発話は AI を呼ばないことを自動テストで確認。
- 既定の整形モデルを `gpt-6-luna` に変更（OpenAI 公式のモデルページで ID を確認）。`reasoning_effort: "none"` を指定し、
  受け付けないモデルでは指定なしで再送する（自動テスト）。
- 応答の `usage` から月ごとの利用回数とトークン数を記録し、設定画面に推定金額を表示（自動テスト）。
- 設定画面の表示はスクリーンショットで確認。

未確認: 実際の API キーでの `gpt-6-luna` 接続（応答時間、整形の品質、`reasoning_effort: "none"` が受け付けられるか）。
