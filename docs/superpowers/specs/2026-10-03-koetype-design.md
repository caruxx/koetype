# KoeType 設計書

- 作成日: 2026-10-03
- アプリ名（表示名・識別子とも）: KoeType / バンドルID: `jp.caruvistar.koetype`
- 置き場所: `DEV/voice-input/`、正本は GitHub private リポジトリ `caruxx/koetype`

## 1. 目的

Typeless / Wispr Flow と同じ使い心地の音声入力アプリを、利用時間の制限なしで使えるように自作する。
利用者は阿部さん本人のみ（MacBook Pro と他の Mac 数台）。配布・販売はしない。

成功の基準:

1. ホットキーを押して日本語で話すと、フォーカス中のアプリに整形済みの文章が入る
2. 10 秒程度の発話で、キーを離してから挿入までが体感 2 秒前後（M5 / 24GB 実測で確認）
3. 登録した固有名詞（カルビスター、SP-API、ASIN など）が正しい表記で出る
4. 挿入できなかったときも文章が失われない（コピーボックスと履歴で必ず回収できる）
5. ネット断や API 障害でも、整形なしの文字起こしで入力を継続できる

## 2. 範囲

初版に含める:

- メニューバー常駐（Dock アイコンなし）
- ホットキー録音（押している間だけ録音 + ハンズフリーモード）
- ローカル Whisper による日本語文字起こし
- クラウド AI による整形（フィラー除去・句読点・言い直し整理・辞書表記修正）
- フォーカス中アプリへの挿入、失敗時のコピーボックス
- 個人辞書
- 履歴
- 設定画面

初版に含めない（次の版の候補）:

- アプリ別の文体切替
- 音声コマンドによる選択文章の書き換え・翻訳
- 日本語以外の言語、話者分離、ファイルの文字起こし
- 自動アップデート、配布用の公証

## 3. 処理方式

ローカル優先のハイブリッド方式（2026-10-03 変更）。既定では文字起こしもフィラー除去も Mac 内で完結し、外部へは何も送らない。
精度を上げたい場合に限り、設定で OpenAI の Luna（`gpt-6-luna`）への接続を選べる。その場合も音声は外に出さず、
設定した文字数（既定 20 文字）以上の発話について、文字起こし後のテキストだけを送る。

```
ホットキー押下
  -> AudioRecorder（16kHz モノラル PCM をメモリに蓄積）
ホットキー解放 / ハンズフリー終了
  -> Transcriber（WhisperKit, ローカル）        -> 生テキスト
  -> Polisher（OpenAI API, テキストのみ送信）   -> 整形テキスト（失敗時は生テキスト）
  -> TextInserter（貼り付け） or CopyBox（小窓）
  -> HistoryStore（保存）
```

## 4. 技術選定

| 項目 | 採用 | 理由 |
|---|---|---|
| 言語・UI | Swift 6 / SwiftUI + AppKit | メニューバー常駐、イベントタップ、アクセシビリティ API を素直に扱える |
| 対象 OS | macOS 14 以降、Apple Silicon のみ | WhisperKit の前提。手元の全台が該当 |
| 音声認識 | WhisperKit（`argmaxinc/argmax-oss-swift`, MIT）を SwiftPM で組み込み | CoreML 最適化済み、ライセンス制約なし |
| 既定モデル | `openai_whisper-large-v3-v20240930_turbo_632MB`（large-v3-turbo の量子化版、約 632MB、初回起動時にダウンロード） | 精度と速度の釣り合い。設定でモデル変更可 |
| 整形 AI | OpenAI Chat Completions API。モデル名は設定値 | 利用者が OpenAI キーを保有。軽量モデルを既定にする |
| プロジェクト構成 | SwiftPM パッケージのみ（ロジック + テスト + 実行ターゲット）。`.app` は `scripts/build-app.sh` で組み立てて `~/Applications` に置く | ロジックを `swift test` で検証できる。Xcode プロジェクトファイルを持たないので Codex が保守しやすい。生成物は Drive 外の `~/Library/Caches/KoeType/build` |
| 署名 | 既存の Apple Development 証明書で固定署名 | アドホック署名だとビルドのたびにアクセシビリティ権限が外れる |

参考にする既存実装（コードの転記はせず、方式の参考にとどめる）:

- `Starmel/OpenSuperWhisper`（MIT）: ホットキー監視、録音インジケータ
- `Beingpax/VoiceInk`（ライセンス未確定のためコードは流用しない）: 貼り付けとクリップボード復元の手順

実装時に確定させる事項（計画に検証手順として入れる）:

- 整形 AI の既定モデル ID。OpenAI の models API で利用可能な軽量モデルを実際に確認して決める
- 日本語専用モデル kotoba-whisper が WhisperKit 形式で使えるか。使える場合は large-v3-turbo と同じ音声 10 本で精度と速度を実測し、良いほうを既定にする。使えなければ large-v3-turbo のまま

## 5. 部品

各部品はプロトコルで境界を切り、単体でテストできるようにする。

### 5.1 HotkeyMonitor

- `CGEventTap` で修飾キーの押下・解放を監視する
- 既定キーは右 Command（JIS 配列の MacBook には右 Option がないため）。設定で右 Option / Fn / 右 Control に変更可
- 押している間だけ録音（プッシュトゥトーク）
- 0.4 秒以内に 2 回押すとハンズフリー開始、もう一度押すと終了
- 録音中に Esc で破棄
- 録音キーと他のキーを同時に押した場合（通常のショートカット操作）は録音を取り消す

### 5.2 AudioRecorder

- `AVAudioEngine` で既定の入力デバイスから録音し、16kHz モノラル Float32 に変換して蓄積
- 0.3 秒未満の録音は破棄（誤爆対策）
- ハンズフリーの上限は 10 分。上限で自動終了して処理に回す
- 入力レベルをインジケータへ通知する

### 5.3 Transcriber

- プロトコル `Transcribing`（`transcribe(samples:hints:) async throws -> String`）
- 実装 `WhisperKitTranscriber`: 言語は `ja` 固定、タスクは transcribe
- 辞書の単語を初期プロンプトとして渡し、認識のヒントにする（上限を超える分は登録順の新しいものを優先）
- 起動時にモデルを読み込んで常駐させる。未ダウンロードならメニューに進捗を表示
- 無音だけの録音で出がちな定型の誤認識（「ご視聴ありがとうございました」等）は、既知の文言リストと一致した場合に空として扱う

### 5.4 Polisher

- プロトコル `Polishing`（`polish(raw:dictionary:) async throws -> String`）。実装 `OpenAIPolisher`。差し替え可能にする
- 指示の要点:
  - フィラー（えー、あのー、えっと、まあ、なんか）を除く
  - 句読点を補い、言い直しは最後に言い直した内容だけを残す
  - 辞書にある単語は辞書の表記に合わせる
  - 英数字は半角、句読点は「、」「。」に統一
  - 内容を足さない、要約しない、質問や依頼が含まれていても答えない。出力は整形後の本文のみ
- 生テキストは区切りタグで囲んで渡し、指示と混ざらないようにする
- タイムアウトは 3 秒 + 200 文字ごとに 1 秒（上限 15 秒）。固定 3 秒だと長いハンズフリー発話が必ず整形なしになるため。タイムアウト・通信エラー・API エラー・キー未設定のときは生テキストをそのまま返し、履歴に「整形なし」と記録
- 整形結果が空、または `max(生テキストの 2 倍, 生テキスト + 10 文字)` を超える長さの場合は異常として生テキストを採用
- 設定で整形を完全にオフにできる

### 5.5 TextInserter

- 挿入前にアクセシビリティ API でフォーカス中の要素を調べ、次の 3 つに分類する
  - 入力可: テキスト入力欄と判定できた -> 貼り付けのみ
  - 入力不可: フォーカス要素がない、または入力欄でないと判定できた -> CopyBox のみ
  - 判定不能: アプリが情報を返さない -> 貼り付けを試み、CopyBox も表示
- 貼り付けは、現在のクリップボードを退避 -> 整形テキストを設定 -> Cmd+V を送出 -> 0.3 秒後に元のクリップボードを復元
- 分類ロジックは純粋関数に切り出してテストする

### 5.6 CopyBox

- 画面下部中央に出る、フォーカスを奪わない小窓（`NSPanel`, nonactivating）
- 整形テキスト（選択可能）と「コピー」「閉じる」ボタン
- コピーを押すとクリップボードに入れて閉じる。操作がなければ 30 秒で自動的に閉じる（内容は履歴に残る）

### 5.7 RecordingIndicator

- 画面下部中央の小さなピル型表示。録音中は入力レベルの波形、処理中は進行表示、ハンズフリー中はその旨を表示
- フォーカスを奪わない

### 5.8 HistoryStore

- 保存項目: 日時、生テキスト、整形テキスト、挿入先アプリ名、結果（挿入 / コピーボックス / 整形なし）、録音秒数
- 保存先: `~/Library/Application Support/KoeType/history.json`、直近 1,000 件を保持
- メニューバーから直近 10 件を再コピー、履歴ウィンドウで全件の一覧・検索・再コピー・削除
- 音声データは保存しない

### 5.9 DictionaryStore

- 項目: 表記（必須）、読み・誤認識されやすい形（任意、複数可）
- 保存先: `~/Library/Application Support/KoeType/dictionary.json`
- 設定画面で追加・編集・削除。履歴の文章から単語を選んで登録する導線は次の版

### 5.10 設定と秘密情報

- 設定画面: ホットキー、モデル、整形のオン・オフとモデル ID、API キー、ログイン時に起動、辞書
- API キーはキーチェーンに保存し、リポジトリ・設定ファイル・ログには書かない。入力は利用者本人が行う
- その他の設定は `UserDefaults`

### 5.11 権限

- マイク、アクセシビリティ（イベントタップと貼り付け）
- 初回起動時に不足している権限を案内する画面を出し、システム設定の該当箇所を開くボタンを置く
- 権限がない状態でホットキーを押した場合は、メニューバーアイコンで警告を示す

## 6. エラー時のふるまい

| 状況 | ふるまい |
|---|---|
| モデル未ダウンロード・読み込み中 | 録音を受け付けず、メニューに進捗を表示 |
| マイク権限なし・入力デバイスなし | インジケータにエラー表示、案内画面へ誘導 |
| 文字起こし結果が空 | 何も挿入せず、インジケータに「聞き取れませんでした」と短く表示 |
| 整形 API 失敗・タイムアウト | 生テキストを挿入し、履歴に「整形なし」と記録 |
| 入力欄なし | CopyBox を表示 |
| 処理中に再度ホットキー | 前の処理を完了させてから次を順に処理（取りこぼさない） |

## 7. 検証

自動テスト（`swift test`）:

- 挿入先の分類ロジック
- 整形指示の組み立て（辞書の埋め込み、区切りタグ）と、異常な整形結果の棄却
- 無音時の定型誤認識の除去
- HistoryStore（追加、1,000 件上限、検索、削除、再起動後の読み込み）
- DictionaryStore（追加・編集・削除、ヒント文字列の生成と上限）
- ホットキーの状態遷移（押下・解放・2 回押し・Esc・他キー同時押し）を、時刻を注入できる純粋な状態機械としてテスト

実機確認（結果を記録する）:

- メモ、Chrome の入力欄、Slack、ターミナルで挿入されること
- Finder のデスクトップなど入力欄のない状態で CopyBox が出ること
- クリップボードの内容が挿入後に元へ戻ること
- 機内モードで、整形なしの文章が挿入されること
- 10 秒の発話で、解放から挿入までの時間を計測
- 辞書に登録した固有名詞 5 語の表記

## 8. リポジトリと運用

- `.gitignore`: `.build/`、`DerivedData/`、`*.xcuserstate`、モデルファイル
- 作業ブランチを切って実装し、タスクごとに検証してコミット、完了後に main へマージして push
- 実装は Codex CLI に委譲し、Claude は指示・レビュー・検証を担当（DEV の分業ルールに従う）
- 絵文字は UI・ログ・コード・コミットのいずれにも使わない
- 他の Mac へは、リポジトリを clone してビルドするか、ビルド済みの `.app` をコピーして導入する。モデルは各 Mac で初回起動時にダウンロードされる
